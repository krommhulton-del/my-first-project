# 地利板块体检:先量后改

> 缘起:用户 2026-08-01 原话——「能不能详细地做一下这旺地,我感觉不够专业不够深刻,
> 就是你多查阅一下资料,然后还有就是有一些比如说后面那些大城市做太少了,
> 包括这个类目就是太浅了,我觉得可以生完,然后做得更好一些,慢慢打磨吧」。
>
> 按本项目规矩:**先跑数据找结构性错误,不靠直觉调参**。这份是动手前的实测家底。

---

## 一、坐标库并不小,但用法有两个硬伤

`dili.js` 的 `PLACES` 实测 **449 条**:34 个省级锚 + 415 个市。
拿「城市能级五十强」逐个核,**一个都不缺**。所以「城市少」不是库的问题,是**排序与筛选**的问题。

### 硬伤一:四个直辖市根本进不了城市榜(结构性)

`RAW` 里 `*` 开头表示省级锚。北京、天津、上海、重庆**只有省级那一条**,没有对应的市级条目。
而 `recommend()` 里的城市榜是:

```js
const cities = scan(false)   // scan(false) 只取 p[3] === 0,即非省级
```

于是**北上津渝四市被永久排除在「旺方向上的大城市」之外**。
广州能出现,只是因为 `*广东` 与 `广州` 在 RAW 里各占一条(同坐标)——纯属巧合,不是设计。

### 硬伤二:城市榜按距离升序取前 8,于是永远是小城

```js
const cities = scan(false).filter(...).sort((x, y) => x.km - y.km).slice(0, 8);
```

449 条里混着仙桃、潜江、天门这类县级市,按距离近的先排,**大城市根本挤不进前 8**。实测:

| 现居 | 程序给的「旺方向上的大城市」 |
|---|---|
| 武汉 | 黄石(81km) 咸宁(89) 信阳(168) 九江(192) 安庆(259) 南昌(262) 驻马店(268) 浏阳(275) |
| 上海 | 海门(83km) 慈溪(113) 余姚(136) 宁波(145) 舟山(149) 嵊州(190) 临海(259) 台州(278) |
| 成都 | 资阳(82km) 眉山(83) 乐山(126) 遂宁(145) 内江(156) 自贡(159) 南充(191) 宜宾(217) |
| 北京 | 唐山(157km) 沧州(181) 衡水(252) 秦皇岛(273) 德州(278) 滨州(311) 东营(332) 济南(360) |

标题写着「大城市」,给出来的却是黄石、资阳、衡水。**用户说的「大城市做太少了」,指的就是这个。**

### 硬伤三:省级判断被省会坐标绑架

省的方位取的是省会坐标(浙江锚杭州、山东锚济南)。省这么大,拿一个点代表它,结论会失真。
以「居上海、旺向为正北/正东/东南/正南」这一命实测:

| 省 | 省会锚点方位 | 整省判定 | 省内实况 |
|---|---|---|---|
| 浙江 | 杭州 231°=**西南** | 整省出局 | 24 市里 **11 个**在旺向:宁波 176°正南、温州 192°正南、舟山 153°东南、台州 182°正南 |
| 山东 | 济南 327°=**西北** | 整省出局 | 30 市里 **16 个**在旺向:青岛 350°正北、烟台 359°正北 |

浙江近半、山东过半的城市都在这人的旺向上,却因为省会一个点全被抹掉。

> **更正**:这一节初稿我写的是「江苏(锚南京)被判出局,可南通、盐城、连云港明明在上海正北」。
> 实测不成立——南通 328°、盐城 333°、连云港 331°,全是**西北**,与省会南京(292°正西)同属忌方,
> 江苏并不是失真案例。上面换成了实测站得住的浙江与山东。**例子是我举错的,数字没错。**

## 二、类目确实浅:两层而已

现在的 `judge()` 只有一层主判 + 一层旁注:

1. **方位五行**:目标地相对现居地的方位角 → 八方 → 五行 → 对喜忌 → 五档(大旺/旺/平/偏背/背)
2. **神煞旁注**:驿马方 / 天乙贵人方 / 桃花方 / 流年岁破方

就这些。没有照到的:

- **目的地本身是什么地方**——深圳与鞍山若同在你的旺向上,程序给的是**一模一样**的断语。
  海港、钢城、林区、油田、瓷都,在现在这套里毫无区别。
- **寒暖燥湿**——这是《穷通宝鉴》整本书的骨架,程序里已经有 `Bazi.tiaoHou` 算调候,
  地利板块**一个字都没用**。冬生金水寒的人该往南,夏生火炎土燥的人该往北,这是本项目现成能算的,却没接上。
- **什么时候动**——板块完全没有时间维度。只答「哪儿」,不答「哪年」。
- **去了干什么**——没有行业/职业方向。
- **距离远近怎么算**——只有一条 80 公里的硬门槛,过了就一视同仁,3000 公里与 300 公里同判。

## 三、输入比别处少一项:没有时辰

板块只收「生日 + 现居地」。可 `dlChart()` 走的是 `dxBirthChart('q')`,
它在**背地里**从 `localStorage` 取时辰,取不到就按中午 12 点算:

```js
const hour = hv === '' ? 12 : (Number(hv) === 0 ? 23 : Number(hv) * 2 - 1);
```

而喜用神对时辰极敏感(自测:同一天十二个时辰里有七个触发从格,喜忌整个翻转)。
**界面上不摆时辰,等于让人以为地利只看生日。** 这与待办队列第 7 条「要精确到时辰」是同一件事。

## 四、查了资料:古籍支持什么、不支持什么

按铁律六与第七节的规矩,动手前先在 `data/classics/` 五本原文里查了一遍。**结论对本板块不利,照实记。**

### ① 子平古籍里的「南方」「东方」指的是大运,不是地理

`滴天髓阐微` 里「南方」出现 60 次、「北方」45 次、「东方」35 次,逐条看上下文,全是**行运**:

- 「运行东南方,宜乎巨富」
- 「幼年行南方运,赖火生土」
- 「癸丑北方阴湿之地,金水通根」——这里的「北方之地」是亥子丑运,不是地图上的北方
- 「庚寅,东方木地」——寅卯辰运

**没有一条是说「搬到南边去住」。** 所以方位配五行这一层,在我手上这五本书里**找不到出处**,
它来自《易·说卦》与堪舆一脉,不在库内。**照旧标「通行口径,出处待核」,不许挂书名。**

### ② 神煞这一层,两本书打架——必须两头都说

- `增删卜易`(繁体)明写:「貴人祿神驛馬亦必附和用神之旺相﹐卽不能獨操禍福之權」
  ——神煞**不能单独定吉凶**,只能附在用神旺相上。
- `滴天髓阐微` 说得更狠:「咸池驛馬,是后人之谬言」——直接否掉。

程序现在把驿马方/桃花方/贵人方与主判并排摆着,看上去分量相当。
**改法:这一层明确降为旁注,并把两本书的分歧当面写给用户看。**不许只挑对自己有利的那本引。

### ③ 有一条真能挂出处的:驿马与「出外」

`滴天髓阐微`:「申运驿马逢财,出外大利,经营得财十余万」——这是**出外**得利的实例,
且与驿马、财星连着说。这条可以挂,但它说的是**运**上的驿马,不是方位上的驿马,挂的时候要说清。

### ④ 《增删卜易》有「出行章第九十」,但这份转录里只有目录,正文没下来

抽查确认:章目里列着「出行章第九十」,正文段落搜不到(该本 123 章只转录了 85 章)。
另有一处别章引用「出行章云﹕路上有官休出…」,是转述不是原章。
**所以六爻复核这一路暂不挂《增删卜易·出行章》的名。**

## 五、这一版要动的(按上面量出来的洞排)

| # | 洞 | 修法 |
|---|---|---|
| 1 | 四直辖市进不了城市榜 | place 加「城市能级」字段,直辖市按城市参与排名 |
| 2 | 城市榜按距离排,永远是小城 | 改按能级优先 + 综合分,并分档摆出来 |
| 3 | 省被省会绑架 | 省级结论改由该省**所有市**的实际方位加权得出,并注明省内分歧 |
| 4 | 类目只有两层 | 补到七层:向 / 气 / 候 / 煞 / 时 / 业 / 程 |
| 5 | 没有时辰输入 | 板块摆出时辰,并当面说明喜忌随时辰变 |
| 6 | 神煞与主判并排 | 降为旁注,写明两本书的分歧 |
| 7 | 调候算了却没用上 | 接 `Bazi.tiaoHou`,南北寒暖入判 |

**不动的**:方位角实算(球面公式已有外部对照测试)、80 公里同城门槛、五档主判的口径。
