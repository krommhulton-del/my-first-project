# 姻缘方向 01 · 为什么把它整个撤下来

**一句话结论:姻缘的吉凶方向,命盘算不出来;能算出来的那个东西,程序压根没问。**
所以 v0.77 把这一类的无条件吉凶方向**整个撤下**,只留「哪一年动、动多重」,方向留给用户自己的处境。

这是 CLAUDE.md 待办队列第 0 条,挂了两轮没动——前两轮的结论都是「卡在语料上」。
这一轮换了个问法:不问「怎么把它修准」,先问「它到底能不能算准」。答案是不能,于是撤下。

---

## 一、先摆数字:这个洞有多大

回测语料 33 人里有 **37 件姻缘事**(全列在第五节)。按事件本身的性质拆开:

| | 件数 | 好事 | 坏事 | 好事占 |
|---|---|---|---|---|
| **结合类**(结婚/订婚/同居) | 28 | 25 | 3 | **89.3%** |
| **分离类**(离婚/丧偶/家庭破裂) | 7 | 0 | 7 | **0%** |
| 同年既结又离 | 2 | 0 | 2 | 0% |

好坏几乎完全由「这一年发生的是结合还是分离」决定。这一步没什么玄机。

**关键在下一步:结合还是分离,又由什么决定?** 按当事人进入这一年时的婚姻状态拆:

| 进这一年时 | 件数 | 结合 | 分离 | 好事占 |
|---|---|---|---|---|
| **未见婚**(语料里此前没有结合事件) | 27 | 25 | 2 | **81.5%** |
| **已婚** | 10 | 3 | 7 | **30.0%** |

**这两个变量——事件是结合还是分离、当事人此刻是单身还是有伴——命盘一个都算不出来。**

---

## 二、那程序原来在算什么?——量出来是零区分度

旧法把八条证据(配偶星透干/伏支、合日支、三合日支、红鸾、天喜、桃花、冲日支)
各配一个 +1/−1 的方向,加权求和当作吉凶。成绩:

| 分组 | 表态 | 命中率 |
|---|---|---|
| **全部姻缘** | 21 | **47.6%** ← 比抛硬币还差 |
| 结合类 | 15 | 60.0% |
| 分离类 | 5 | 20.0% |
| 未见婚 | 13 | 53.8% |
| 已婚 | 8 | 37.5% |

更要命的是**控制住状态之后再看**——如果命盘真有信号,同一状态内部它总该能分开好坏吧:

| | 好事的平均方向分 | 坏事的平均方向分 |
|---|---|---|
| 未见婚组 | 0.19 | **0.96**(坏事反而更高) |
| 已婚组 | 1.17 | 1.11(几乎一模一样) |

**零区分度。** 已婚组两个数差 0.06 分;未见婚组方向还是反的(样本 5 件,不作数,但至少没有正信号)。

再看古法那条「合主聚、冲主散」的覆盖率:

- 多数盘上合日支的:**3 / 37**
- 多数盘上冲日支的:**2 / 37**
- 两样都没有的:**32 / 37**

上一轮(v0.62 那次)就量过一遍是 27/32,这一轮扩到 37 件仍是同一个结论:
**这条古法在真实的婚姻年份上基本没有覆盖率**,想拿它区分聚散,先得有它出场的机会。

---

## 三、所以改成什么

**动量归命盘,方向归处境。**

1. **动量**(命盘真算得出来):`dashi.js` 的姻缘分照旧算——哪一年配偶星透出、婚姻宫被合被冲、
   红鸾天喜临门,分越高动得越重。这一层有覆盖率、有古法依据,不动它。
2. **方向**:八条证据的 `dir` 一律改传 0。改传一个新参数 `ju`(聚 +1 / 散 −1)——
   那是「合主聚、冲主散」的说法,但**只作旁注,不计入方向**(理由见上,覆盖率 5/37)。
3. **不填处境就不表态**:`cats.yinyuan.held = true`,断语把两条路都摆出来:
   > 感情上动得最重的一年:眼下单身的,这一动八成往结合上走——见家长、订婚、领证挑这一年办;
   > 眼下有伴的,同一股力多半使在摩擦与聚散上,该摊开的话别拖过年底。**是哪一条,看你此刻的处境,不看命盘。**
4. **填了处境就给方向,但必须标明来源**:`dirFrom = '处境'`,依据里明写
   「这一层是处境定的,不是卦定的」。界面上加了「眼下单身 / 眼下有伴」的选项(主程序顶栏与运势页各一处)。
5. **喂给模型的材料里写死了铁规矩**:「绝对不许自己补一个『这年感情大吉』或『这年必有波折』——那是材料里没有的东西。」

### 顺带的一处连锁改动

**定时辰板块不再拿姻缘事件回推时辰。** 那个板块靠「哪个时辰的吉凶判断与你的经历吻合」定时辰,
既然姻缘的方向已撤下,拿它回推等于拿噪声定时辰。用户只给姻缘类事件时,程序会明说:
「这一类的吉凶方向本程序已经撤下,补几件事业、财运、健康类的事就能算。」

## 四、改前改后的回测数字(必须连口径一起看)

| | 改前(v0.76) | 改后(v0.77) |
|---|---|---|
| 门槛 1.0 命中率 | 70.3%(52/74) | **79.2%(42/53)** |
| 门槛 0.5 命中率 | 69.0% | 76.9% |
| 门槛 0.001 命中率 | 76.1% | 82.2% |
| Fisher 双尾(门槛 1.0) | p=0.0027 | **p=0.0001** |
| 标签整体置换(门槛 1.0) | p=0.0026 | p=0.0002 |
| **按人分层置换(门槛 0.5)** | p=0.0098 ★ | **p=0.0012 ★** |
| **按人分层置换(门槛 1.0)** | p=0.0676 ✗ | **p=0.0446 ★** |
| 表态数 | 74 | **53** |

**这组数字必须这么读,不许读成「程序变准了」:**

命中率从 70.3% 涨到 79.2%,**不是因为断得更准了,是因为把断不准的那一类闭嘴了**。
表态数从 74 掉到 53(少了 21 件,正好是原来姻缘的表态数)。
剩下那 53 件的判断**一个字都没改**——同样的盘、同样的规则、同样的答案。

这是**校准**上的改进(程序不再在自己没有信号的地方开口),不是**能力**上的改进。
两者不是一回事,不许混着说。

值得记一笔的是:**按人分层置换检验,这是第一次两个门槛都过线**(此前两轮回测都只在一个门槛上过,
而且过线的门槛还换过)。但门槛 1.0 那个 p=0.0446 只是刚过 0.05,离「稳」还远,**照旧不许说「准」**。

## 六、这份分析自己的毛病(不许假装没有)

1. **「事发前状态」是我从语料里推的,不是语料自带的字段。** 推法:同一人此前有过结合事件即算已婚,
   有过分离事件即回到单身。**这个推法对语料覆盖不全的人是错的**——
   例如爱因斯坦 1919 年离婚,而他 1903 年的结婚不在语料里,于是被推成「未见婚」。
   所以第一节那张状态表的绝对数字不可尽信,**但它的方向不受影响**:
   分离类事件必然发生在已婚状态,这一点是定义决定的,不靠推。
2. **结合/分离是按事件文字里的关键词分的**(结婚|成婚|订婚|再娶 vs 离婚|逝世|遇害|破裂)。
   分类规则写在 `docs` 之外的探针脚本里,不入库——**这意味着这张表不可机器复现**,是本文的一处弱点。
   真正入库、有测试盯着的是撤下方向这件事本身(`tests/dashi.test.mjs` 的姻缘四条)。
3. **37 件、33 个人、全是名人。** 名人的婚姻被记录下来的本就偏向大事,普通人的
   「谈了三年分手」「相亲没成」根本进不了语料。样本的形状与真实人群不一样。
4. **没有反例。** 语料里只有「发生过的事」,没有「这一年感情上什么都没发生」。
   所以这份分析只能考「方向」,考不了「有没有」——而用户真正想问的往往是后者。
5. **撤下方向之后,「填了处境就给方向」那一层没有被回测检验过,也不该被检验。**
   用户自述的处境不是命盘算出来的,拿它去刷回测命中率等于作弊。
   那一层的依据只有第一节那张表(单身 81.5% 好、有伴 30% 好),**它是基础比率,不是卦理**,
   界面上已经这么写了。

## 七、要真正修好它,还缺什么(与上一轮结论一致)

一份**姻缘专项语料**:普通人、60–80 件以上、结合与分离各占一半、确切年份、
好坏由当事人自己判、同一人给两三件、并且**带上当年的婚姻状态**。
有了它才谈得上「命盘能不能在处境之上再多说一点」。在那之前,程序只报窗口,不报吉凶。
