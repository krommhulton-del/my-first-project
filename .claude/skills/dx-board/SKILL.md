# 东玄卜卦 · 新板块 SOP

顺序不能反:**引擎 → 测试 → 界面 → 端到端 → 口径巡检 → 发版**。
先做界面会让断法迁就界面,那是这个项目最忌讳的事。

## 一、先想清楚三件事(动手前写下来)

1. **这个板块回答的是哪一句话?** 一句话说不清,说明还没想清楚。
2. **答案由什么算出来?** 列出所依据的术数要件与出处口径。
   凡是「让模型自己发挥」的部分,一律砍掉重想——见 `CLAUDE.md` 第五节。
3. **它跟已有板块共用什么?** 喜忌一律取 `chart.yong`;命盘一律走 `dxBirthChart()`。
   **不许**自己再实现一套旺衰或取用神。

## 二、写引擎(独立 .js 模块)

- UMD 包装,与现有模块一致:`module.exports` / `root.Xxx`。
- 文件抬头写清**断法依据**:每一条规则出自什么口径。出处不确定的写「通行口径,出处待核」,**不许编书名章节**。
- **每一条结论都要带可追溯的依据串**,能在界面上摊开给人看。
- 提供 `material()`,把程序算死的结论交给 AI,并在末尾写明:
  「已由程序算死,勿另立结论」+ 写法要求 + 禁空话清单。

## 三、写测试(界面之前)

新建 `tests/<board>.test.mjs`,抬头写「缘起」。至少覆盖:

- **正确性**:关键规则拿外部标准对照(能对照的话)
- **自洽性**:依据方向与结论方向一致——不许「依据说吉、结论说凶」
- **边界**:年龄闸门、样本为空时照实说没有(**不许硬编**)、性别相关取法翻面
- **措辞**:跨尺度用词换口径(年/月/日不能混用「流年」「这一年」);禁空话清单

并进 `package.json` 的 test 链。

## 四、做界面

- **卡片**加进 `#board-menu`,**id** 加进 `BOARD_IDS`。
- **id 前缀查重**:已占用 `wj- wq- jr- xy- yl- dl- zy- dw-`(见 `CLAUDE.md`)。
  撞车会导致 `#xxx` 解析到两个元素,e2e 直接炸——已经发生过一次。
- **常量名查重**:新加的 `const` 要 grep 一遍。`PKEY` 重名曾让整页脚本不执行、主程序白屏。
- 生辰输入与全局共用(`BKEY/HRKEY/PLKEY/GKEY`),填一次全应用通用。
- 结论区第一句就是答案;依据折叠或次级样式;末尾一句口径说明(这是窗口不是保票)。
- 手机优先:窄屏下不许横向溢出。

## 五、脚本登记三处

`index.html` 的 `<script src>`、`sw.js` 的 `ASSETS`、`build-single.mjs` 的内联清单。漏一处会在某个版本里失效。

## 六、端到端

在 `tests/e2e.mjs` 加一项:打开板块 → 填生辰 → 点一个快捷问 → 断言关键结论出现、无空话、按钮就位。
必要时在 `tests/single-e2e.mjs` 也加一项,确认单文件版可用。

## 七、口径巡检

跑 `tests/consistency.test.mjs`。它守着两条结构铁律:
`Bazi.chart` 全应用只许调用一次;各模块不许自己实现 `judgeStrength` / `pickYongShen`。

## 八、收尾

更新 `CLAUDE.md`(架构表新增一行、id 前缀表、待办队列),然后走 `dx-release`。
